Project Manual & Operations Guide

AI-Based Energy Consumption Prediction System • MCA Major Project

Section 1 • How to Run the Project (Step-by-Step)

Open PowerShell or Command Prompt and run these commands in order from the ml-service folder:

Step 0: Navigate to Project Directory

cd D:\energy-consumption-ai\ml-service

Step 1: Run All 42 Automated Unit Tests

Verifies code integrity, data loaders, feature formulas, and zero-leakage constraints:

python -m unittest discover -s tests -v

Expected Terminal Output: Ran 42 tests in ~1.5s ... OK

Step 2: Run Baseline Model Benchmark

Aggregates raw data into hourly intervals, trains Persistence, Linear Regression, and Random Forest, and generates comparison charts:

python scripts/train_model.py

What it creates on disk:

  • data/processed/hourly_consumption.csv (Cached hourly series, 34,589 rows)
  • models/random_forest.joblib (Trained original model, 201.7 MB)
  • reports/metrics/model_comparison.csv (Benchmark scores)
  • reports/figures/model_mae_comparison.png (Comparison bar chart)
  • reports/figures/model_comparison_actual_vs_predicted.png (Time-series tracking)

Step 3: Run Hyperparameter Tuning

Runs a 20-configuration search strictly on the validation set, selects the best model, and saves the regularized binary:

python scripts/tune_model.py

What it creates on disk:

  • models/random_forest_tuned.joblib (Winning 23.8 MB model)
  • models/random_forest_tuned_metadata.json (Configuration & metadata)
  • reports/metrics/random_forest_tuning.csv (All 20 candidate trial scores)
  • reports/figures/model_tuning_comparison.png (Tuning delta chart)

Step 4: Run a Live Prediction (Interactive Demo)

Generates an instant forecast for the next hour using your newly trained model:

python -m src.ml.predict --lag-1 1.25 --lag-2 1.10 --lag-3 1.05 --lag-24 1.30 --rolling-3h 1.13 --rolling-24h 1.22 --hour 18 --day-of-week 2

Output you will see on screen:

Model: models/random_forest_tuned.joblib
Prediction for target (Global_active_power at hour t+1): 1.37 kW

When you want to clear all trained models and outputs to run everything from scratch by yourself, follow these rules:

Section 4 • Presentation Script

How to Explain the Project in Simple Words

If a professor, examiner, or interviewer asks: “Can you introduce your project and what it does?”, speak this exact 60-second summary:

“My project is an AI-Based Energy Consumption Prediction System. The objective is to accurately forecast how much electricity (mean active power in kilowatts, kW) a home will consume in the next one hour.

I used 4 years of real smart-meter telemetry from the benchmark UCI Individual Household Electric Power Consumption dataset (over 2 million raw readings). I aggregated the readings into continuous hourly intervals and engineered 8 leak-free autoregressive and calendar features derived strictly from past data.

To rigorously test the models, I established a strict chronological evaluation partition: 70% training, 15% validation, and 15% untouched held-out test data. I compared four models: a Persistence baseline, Linear Regression (OLS), an Original Random Forest, and a Tuned Random Forest.

The Tuned Random Forest performed best, achieving a test MAE of 0.3239 kW—a 13.12% error reduction compared to the baseline. Most importantly, by tuning tree depth to 10, we achieved structural regularization that reduced the model's file size by 88% (from 201 MB down to 24 MB) without losing accuracy, making it ideal for edge deployment in real smart meters.”

Section 5 • Viva & Interview Cheatsheet

Clear, direct answers to common examiner questions:

Q1: What dataset does your project use?
Answer: The UCI Machine Learning Repository Dataset #235 (Individual Household Electric Power Consumption). It contains 47 months of sub-minute electricity telemetry (2,075,259 records from Dec 2006 to Nov 2010) collected from a single home in Sceaux, France.
Q2: What is the target variable you are predicting?
Answer: We predict target, which is the mean household active power at hour t+1 (Global_active_power measured in kilowatts, kW).
Q3: What features are used, and how do you prevent data leakage?
Answer: Exactly 8 causal features are used. Zero future data is leaked because all features use telemetry strictly from time ≤ t:
  • lag_1: Power consumed in current observation hour t (kW)
  • lag_2, lag_3: Power 1 and 2 hours ago
  • lag_24: Power at the exact same hour yesterday
  • rolling_mean_3h: 3-hour moving average (short-term trend)
  • rolling_mean_24h: 24-hour moving average (daily baseline)
  • hour (0–23) and day_of_week (0–6): Calendar cycle features
Q4: How did you split your dataset?
Answer: We strictly used a chronological split without shuffling (70% Train / 15% Validation / 15% Held-Out Test):
  • Train (70%): Dec 17, 2006 to Sep 20, 2009 (24,195 hours) — Model fitting.
  • Validation (15%): Sep 20, 2009 to Apr 24, 2010 (5,185 hours) — Tuning & selection only.
  • Test (15%): Apr 24, 2010 to Nov 26, 2010 (5,185 hours) — Untouched until final evaluation.

Q6: Why did tuning improve the model, and why is max_depth=10 significant?
Answer: In residential settings, sudden appliance spikes cause extreme variance. Deep trees (depth ≥ 20) memorize these bursts. Capping max_depth=10 acts as structural regularization against noise. It reduced test MAE from 0.3283 to 0.3239 kW while shrinking file size by 88.2% (201.7 MB down to 23.8 MB).
